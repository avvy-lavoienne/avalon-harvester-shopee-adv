C1. Inject.js timing — fetch proxy belum siap pas API call pertama
──────────────────────────────────────────────────────────────────────
  File      : inject.js:557-595
  Type      : Race Condition
  Risk      : Produk halaman pertama tidak ter-harvest
  
  Deskripsi:
  content.js di-inject di document_idle (default Chrome). Shopee React
  app bisa panggil search API (/api/v4/search/search_items) SEBELUM
  inject.js sempat patch window.fetch. Proxy tidak intercept response,
  produk hilang.
  
  Akar masalah:
  - content_scripts di manifest.json tanpa "run_at" → default "document_idle"
  - Inject.js di-load via <script> tag yang async → timing tidak deterministic
  
  Fix:
  1. Set "run_at": "document_end" di manifest.json
  2. Split content.js: buat minimal inject.js loader di file terpisah
     dengan "run_at": "document_start"
  
  File affected: manifest.json, content.js

──────────────────────────────────────────────────────────────────────
C2. Fetch proxy try-catch brace corruption
──────────────────────────────────────────────────────────────────────
  File      : inject.js:574-584
  Type      : Syntax Error
  Risk      : Extension crash saat intercept API response
  
  Deskripsi:
  Struktur try-catch rusak akibat edit berulang. Kode saat ini:
    try {
      if (...) { ... }
      /* swallow parser errors */
      } catch (e) {       ← brace nutup try sebelum catch
    }
  
  Akar masalah:
  Brace } di line 583 nutup try block, lalu catch(e) { line 583 juga.
  Ini membuat catch tidak terikat ke try mana pun.
  
  Fix:
  Hapus extra } di baris 583. Struktur yang benar:
    try {
      if (...) { ... }
    } catch (e) {
      /* swallow parser errors */
    }
  
  File affected: inject.js

──────────────────────────────────────────────────────────────────────
C3. currentPage display inconsistency (0 vs 1)
──────────────────────────────────────────────────────────────────────
  Files     : background.js:727, popup.js:63-65
  Type      : Off-by-one
  Risk      : User melihat "Page 0/12" terus-menerus
  
  Deskripsi:
  background.js set currentPage: 0 di storage.
  content.js increment currentPage++ SEBELUM scroll → page 1.
  Tapi popup polling GET_STATUS yang baca storage → currentPage masih 0
  karena content.js belum update storage.
  
  Flow:
  1. background set storage { currentPage: 0 }
  2. Tab navigate → content.js startSweep()
  3. startSweep: if (currentPage < maxPages) → 0 < 12 = true
  4. currentPage++ → 1
  5. Scroll + harvest page 1
  6. Click Next → currentPage++ → 2
  Tapi GET_STATUS baca dari storage yang diset background, bukan dari
  memory content.js.
  
  Fix:
  Mulai currentPage: 1 di storage agar popup nampilin "Page 1/12".
  Atau content.js harus update storage setiap page increment.
  
  File affected: background.js

──────────────────────────────────────────────────────────────────────
C4. KEYWORD_FINISHED — missing currentPage/maxPages params
──────────────────────────────────────────────────────────────────────
  File      : content.js:150-160
  Type      : Missing Parameter
  Risk      : background.js pake message.currentPage yang undefined
  
  Deskripsi:
  Saat tombol Next tidak ditemukan dan currentPage >= maxPages,
  content.js kirim KEYWORD_FINISHED tanpa currentPage dan maxPages:
  
    chrome.runtime.sendMessage({
      action: "KEYWORD_FINISHED",
      completed,
      currentPage,
      maxPages
    });
  
  TAPI di path lain (stopSweep atau isSweeping=false), tidak ada
  KEYWORD_FINISHED sama sekali. Task tidak pernah di-update.
  
  Juga, message.currentPage di background.js:814 pakai value untuk
  log message — kalau undefined, log nampilin "undefined/undefined".
  
  Fix:
  1. Pastikan KEYWORD_FINISHED selalu dikirim dengan currentPage dan maxPages
  2. Di stopSweep, kirim KEYWORD_FINISHED dengan completed=false
  
  File affected: content.js

──────────────────────────────────────────────────────────────────────
C5. Hardcoded shopee.co.id di discoverSubCategories
──────────────────────────────────────────────────────────────────────
  File      : background.js:552,559
  Type      : Hardcoded Domain
  Risk      : Gagal di Shopee Thailand/Malaysia
  
  Deskripsi:
  discoverSubCategories buat tab dengan URL hardcoded:
    const tab = await chrome.tabs.create({ url: 'https://shopee.co.id/' });
    const catUrl = cat.url || `https://shopee.co.id/search?facet=${cat.catid}`;
  
  Tidak support shopee.co.th, shopee.com.my, dll.
  
  Fix:
  Deteksi domain dari task (task.domain) atau dari tab yang sudah ada.
  
  File affected: background.js

──────────────────────────────────────────────────────────────────────
C6. host_permissions terbatas ke co.id
──────────────────────────────────────────────────────────────────────
  File      : manifest.json:13
  Type      : Permission Gap
  Risk      : Fetch ke Shopee Thailand/Malaysia di-block Chrome
  
  Deskripsi:
  host_permissions cuma "*://*.shopee.co.id/*".
  Web_accessible_resources juga terbatas.
  Background fetch ke shopee.co.th atau shopee.com.my kena CORS/block.
  
  Fix:
  host_permissions: "*://*.shopee.*/*"
  web_accessible_resources: tambah pattern untuk .co.th, .com.my, dll
  
  File affected: manifest.json

H8. randomDelay — edge case negative/NaN
──────────────────────────────────────────────────────────────────────
  File      : content.js:64-76
  Type      : Edge Case
  Risk      : setTimeout(NaN) → delay 0 → deteksi anti-bot trigger
  
  Math.min(8000, max*0.6) - Math.max(3000, min*0.6) bisa negative
  kalau min > max (misal randomDelay(5000, 3000)). Math.floor(neg) = NaN.
  
  Fix: Guard return Math.max(500, value).

──────────────────────────────────────────────────────────────────────
H9. startSweep page parsing — off-by-one untuk page ke-2
──────────────────────────────────────────────────────────────────────
  File      : content.js:98-100
  Type      : Logic Error
  
  currentPage = (urlPage && !isNaN(urlPage)) ? urlPage - 1 : 0;
  
  Untuk URL ?page=1 (halaman ke-2 Shopee, 0-indexed):
  urlPage = 1, !isNaN(1) = true
  currentPage = 1 - 1 = 0 → loop mulai dari page 1 (0+1) → SCROLL HALAMAN 1 LAGI!
  
  Halaman 2 tidak pernah di-scroll karena loop di-reset ke halaman 1.
  
  Fix: Gunakan urlPage langsung tanpa -1, karena shopee 0-indexed.
